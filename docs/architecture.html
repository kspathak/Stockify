Storage Solutions

04
✓
Recommendation: TimescaleDB + Redis. TimescaleDB gives you PostgreSQL SQL semantics (Spring JDBC works today, zero new drivers), automatic time-partitioning via hypertables, and built-in compression. Redis sits in front for O(1) latest-quote reads without hitting the DB.

Data Schema Design

-- TimescaleDB schema CREATE TABLE stock_prices ( time TIMESTAMPTZ NOT NULL, symbol TEXT NOT NULL, price NUMERIC(12,4), volume BIGINT, bid NUMERIC(12,4), ask NUMERIC(12,4), source TEXT ); -- Converts table into a hypertable partitioned by `time` (7-day chunks) SELECT create_hypertable('stock_prices', 'time', chunk_time_interval => INTERVAL '7 days'); CREATE INDEX ON stock_prices (symbol, time DESC); CREATE TABLE sentiment_signals ( time TIMESTAMPTZ NOT NULL, symbol TEXT, source TEXT, -- 'news' | 'stocktwits' | 'reddit' score FLOAT, -- -1.0 (bearish) to +1.0 (bullish) raw_text TEXT ); SELECT create_hypertable('sentiment_signals', 'time'); CREATE TABLE predictions ( time TIMESTAMPTZ NOT NULL, symbol TEXT, horizon TEXT, -- '1h' | 'eod' direction SMALLINT, -- 1=up, 0=neutral, -1=down confidence FLOAT, actual SMALLINT -- filled in for backtesting );
Redis — Hot Cache
Latest quote per symbol, O(1) reads
  • Key pattern quote:{SYMBOL}
  • TTL 5 seconds
  • Eviction policy allkeys-lru
  • Memory target <256 MB (5000 symbols)
Kafka — Streaming Log
Short-term durable event store
  • Retention 7 days (raw ticks)
  • Partitions 1 per symbol (or 12 hash)
  • Replication 1 (local dev); 3 (prod)
  • Compaction Off for price topics
TimescaleDB — Persistence
Long-term history for ML & backtesting
  • Retention policy Indefinite (or rolling 2yr)
  • Compression Columnar after 7 days
  • Continuous aggregates 1m / 5m / 1h OHLCV
  • Backup pg_dump nightly

Prediction Engine

06
Feature Inputs
Per symbol, per time window

  • Momentum RSI, MACD, Bollinger Bands
  • Volume anomaly z-score vs 30d avg

  • Mention count Social post volume
Model Progression
Phase-gated graduation path
  • Phase 4 Linear regression baseline
  • Phase 4+ LightGBM (tabular, fast)
  • Phase 5 LSTM (sequence, GPU optional)
  • Output Direction signal + confidence
  • Horizon Next 1h, EOD
  • Backtesting Walk-forward, no lookahead
ℹ
Important caveat for business decisions: ML stock price prediction is a hard problem. Academic literature consistently finds that short-horizon directional accuracy rarely exceeds 55–58% on liquid equities. The primary value of this system is the pipeline (real-time data, enrichment, observability) and the signal tooling, not a magic predictor. Treat model outputs as one signal among many, not as trading advice.

Outputs & APIs

07
GET /api/v1/quotes/{symbol}
Returns latest price from Redis cache. Sub-millisecond latency. Fields: symbol, price, bid, ask, volume, timestamp, source.
GET /api/v1/quotes/{symbol}/history?from=&to=&interval=1m
OHLCV candles from TimescaleDB continuous aggregates. Supported intervals: 1m, 5m, 1h, 1d. Returns JSON array, max 10 000 data points per call.
GET /api/v1/sentiment/{symbol}?window=1h
Aggregated sentiment score (–1 to +1) for a symbol over a rolling window. Breakdown by source (news, stocktwits, reddit) included.
GET /api/v1/predictions/{symbol}
Latest model prediction: direction (up/neutral/down), confidence (0–1), horizon (1h / eod), feature snapshot used to generate it.
WS ws://host/ws/quotes/{symbol}
Live price stream via WebSocket. Messages pushed on every new tick received from the upstream provider. Backpressure handled via WebFlux Flux.
STREAM Kafka topic: stock.predictions
All prediction events as a Kafka stream. Any downstream consumer (alerting, portfolio manager, dashboard) can subscribe independently.
